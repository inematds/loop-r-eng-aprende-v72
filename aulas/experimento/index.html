Aula 2 · 20 min

Experimento: manter ou descartar por uma métrica só

O desenho mais limpo de loop que melhora sozinho é curto: o agente muda uma coisa, um comando dá a nota, melhorou fica com commit, não melhorou volta com git reset, e tudo vira uma linha num arquivo. Nesta aula você roda esse ciclo com agentes falsos e depois com o Claude Code de verdade.

Começar a aula

Nesta aula você vai

  1. 1Keep = commit, discard = reset: o git como desfazer
  2. 2Uma métrica só, com orçamento fixo por ciclo
  3. 3results.tsv: toda tentativa vira uma linha, inclusive as ruins
  4. 4O mesmo ciclo com agente falso e com o Claude Code

Objetivo: rodar um experimento no estilo autoresearch: o agente muda, uma métrica decide, git commit se melhorou e git reset se não.

03 · Ensaio: três agentes falsos

O kit cria um repo de triagem (v1) e roda três ciclos: um agente que melhora, um que piora e um que não muda a nota. Nenhum modelo é chamado.

Terminal · ensaio sem custo
K=~/projetos/loop-r-eng-aprende-v72/kit
E=${TMPDIR:-/tmp}/ensaio-aprende/a2
bash $K/novo-sistema.sh $E/sis
for m in sinonimos estraga comenta; do
  AGENTE="bash $K/agente-falso.sh $m" bash $K/experimento.sh $E/sis "$m"; echo "saída: $?"
done
echo "## results.tsv"; cut -f1,3- $E/sis/results.tsv
echo "## git log"; git -C $E/sis log --format=%s

Coluna do hash do commit omitida (muda a cada rodada). O código de saída do experimento.sh diz o que aconteceu: 0 keep, 1 discard, 2 erro.

Tratar agente sem resposta como "não melhorou". Quando a assinatura bate no limite, o agente devolve vazio: o ciclo precisa sair como erro (código 2), senão a fila vira uma série de discards falsos e ninguém percebe que nada rodou. O agente-claude.sh sai com 1 quando a resposta não tem regras, e o experimento.sh registra erro.

04 · O mesmo ciclo com o Claude Code

Uma chamada pela sua assinatura (sai da cota): claude -p sem ferramentas recebe as regras e os casos errados e devolve um regras.txt novo. Quem decide é a medida, não o modelo.

Terminal · real, uma chamada
K=~/projetos/loop-r-eng-aprende-v72/kit
E=${TMPDIR:-/tmp}/ensaio-aprende/a2      # o repo do ensaio acima, já com o keep dos sinônimos
AGENTE="bash $K/agente-claude.sh" bash $K/experimento.sh $E/sis "claude: uma mudança"; echo "saída: $?"
echo "status da última linha: $(tail -1 $E/sis/results.tsv | cut -f5)"
Arquivo · kit/agente-claude.sh
#!/usr/bin/env bash
# agente-claude.sh — o agente REAL do experimento: o Claude Code (sem ferramentas) propõe um regras.txt novo.
# Roda na pasta do repo, chamado pelo experimento.sh. Sai da cota da sua assinatura (uma chamada).
# Resposta vazia (limite da sessão, erro) = ERRO, saída 1: nunca vira "não mudou nada".
set -uo pipefail
K=$(cd "$(dirname "$0")" && pwd)
PEDIDO="Você melhora as regras de um classificador de mensagens de suporte. Formato de cada linha: 'categoria: palavra, palavra'; a primeira categoria cuja palavra aparece no texto vence; sem nenhuma, 'outros'.
Regras atuais:
$(cat regras.txt)

Casos que o classificador errou:
$(python3 "$K/medir.py" . --erros | tail -n +2)

Proponha UMA mudança que generalize (palavras que pessoas reais usariam), sem copiar frases inteiras dos casos.
Responda SÓ com o conteúdo completo do novo regras.txt, sem explicação e sem cercas de código."
J=$(mktemp)
echo "$PEDIDO" | claude -p --tools "" --output-format json > "$J" 2>/dev/null
python3 - "$J" <<'PY'
import json, os, sys
try:
    d = json.load(open(sys.argv[1], encoding="utf-8"))
except Exception:
    print("ERRO: resposta do claude não é JSON"); sys.exit(1)
r = (d.get("result") or "").strip()
linhas = [l for l in r.splitlines() if not l.startswith("```")]
if d.get("is_error") or not any(":" in l for l in linhas):
    print("ERRO: sem regras na resposta (" + (r[:80] or "vazia") + ")"); sys.exit(1)
u = d.get("usage") or {}
ent = u.get("input_tokens", 0) + u.get("cache_read_input_tokens", 0) + u.get("cache_creation_input_tokens", 0)
if os.environ.get("TOKENS_ARQ"):
    open(os.environ["TOKENS_ARQ"], "w").write(f"{ent} {u.get('output_tokens', 0)}\n")
open("regras.txt", "w", encoding="utf-8").write("\n".join(linhas).strip() + "\n")
print(f"regras.txt reescrito ({len(linhas)} linhas)")
PY
rc=$?; rm -f "$J"; exit $rc
Exemplo do repositório
ciclo 4 · keep · 0.800 → 0.900 · melhorou
saída: 0
status da última linha: keep

Uma rodada. O modelo acrescentou palavras de entrega (pacote, encomenda, transportadora, frete…) e a nota visível foi de 0.800 a 0.900. A sua rodada pode dar keep ou discard: o "pronto quando" confere só que a linha foi registrada. Na aula 6, esta mesma mudança é reprovada pelos casos escondidos.

05 · Prática

Ensaio, real e o seu sistema.

E4 · Três ciclos sem custo

10 min

Rode o ensaio.

Pronto quando: cut -f5 $E/sis/results.tsv | sort | uniq -c → 1 keep e 2 discard; git -C $E/sis log --oneline | wc -l → 2.

E5 · Um ciclo real

5 min

Rode o bloco real logo depois do ensaio.

Pronto quando: wc -l < $E/sis/results.tsv → 5 (cabeçalho + 4 ciclos) e a última coluna de status é keep, discard ou erro, nunca vazia.

E6 · O seu medidor

30 min

No seu sistema, escreva o comando que imprime a métrica da sua hipótese (aula 1) como número numa linha, no formato do medir.py --valor. Troque o medir.py do experimento.sh pelo seu (ou adapte o seu sistema ao formato regras + casos).

Pronto quando: o seu comando de medida, rodado duas vezes seguidas sem mudança, imprime o mesmo número; e um ciclo com o agente-falso.sh comenta adaptado ao seu repo termina em discard.

07 · Em três frases

Uma mudança, uma notaCada ciclo mede a base, deixa o agente mudar uma coisa e mede de novo com o mesmo comando.
Git desfazMelhorou é commit; igual ou pior é reset. Nada fica pela metade.
Tudo registradoresults.tsv guarda keep, discard e erro; resposta vazia do modelo é erro.
