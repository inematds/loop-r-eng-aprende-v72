The lessons

In the order the loop learns: write the hypothesis, test it, decide and promote, save the lesson, make it binding, protect the meter, measure the cost, and put it all together in your own system.

  1. Lesson 1 · 15 minA hypothesis with a numberA loop that learns starts with a sentence that can turn out wrong. "Improve the triage" is never wrong, so it teaches nothing. In this lesson you write the hypothesis with process, metric, current, target, measurement command, and what must not get worse, and you work out how long the test takes before you run it.
  2. Lesson 2 · 20 minExperiment: keep or discard based on a single metricThe cleanest design for a loop that improves on its own is short: the agent changes one thing, a command gives the score, if it improved it stays with a commit, if it didn't it goes back with git reset, and everything becomes one line in a file. In this lesson you run this cycle with fake agents and then with the real Claude Code.
  3. Lesson 3 · 20 minDecision card, promotion and rollbackA keep in the lab is not the official version yet. In production, the new version only goes up when the verdict says B won without making anything worse, someone approves it from the five-line card, and there is a way back that deletes nothing. In this lesson you redo the published verdicts from the LOOP-R example, promote, and roll back.
  4. Lesson 4 · 20 minLessons and rules: batch approval and review of an expired ruleThe other side of the loop that learns is not a number: it is the lesson the agent draws from a mistake. Written straight into CLAUDE.md, it only grows, and nobody decides on it or reviews it. In this lesson you use SIL Loop R: occurrence, proposal, batch approval with an explicit decision, and automatic review when the rule's file changes.
  5. Lesson 5 · 18 minPromotion to AGENTS.md and binding ruleAn approved rule that lives only in a database does not reach a new session: it only exists if someone remembers to look it up. In this lesson you ask the promotion question, record the protection rung and the known leak, write the block into AGENTS.md with a diff first, and watch check flag it when someone edits the block by hand.
  6. Lesson 6 · 18 minThe risk of optimizing against your own meterA loop that improves itself will find the shortest path to a higher score, and the shortest path isn't always improving the system: it can be memorizing the cases or tampering with the meter. In this lesson you watch both shortcuts become a keep, close them with a meter frozen outside the repo and hidden cases, and watch a real Claude change get discarded.
  7. Lesson 7 · 18 minObservability: traces and cost per cycleA loop that runs on its own must leave a trace: how long each cycle took, how many tokens it spent, what it decided and why. Without it, an error loop or a cycle that blows your quota only shows up at month's end. In this lesson you record one line per cycle and use it to get cost per cycle, cost per keep, and the alerts.
  8. Lesson 8 · 20 minAssemble LOOP-R in your systemThe seven lessons gave you the pieces: hypothesis, experiment, promotion, lessons, binding rule, protected meter, and trace. What's left is putting them together in your system and checking that none was left out. This lesson also closes the track: what each of the six courses puts into the loop, and the dated plan to assemble yours.

Who it's for

  1. 1You already use Claude Code or Codex in the terminal and want the agent to get better over time, without promoting noise.
  2. 2You have a process with a number (triage, proposal, support, build) and want to test changes with a clear rule for keeping or discarding them.
  3. 3You collect lessons in a CLAUDE.md that only grows, and you want a decision, a review, and a binding rule.

What you'll be able to do

  1. 1Write a hypothesis with a number and know, before you run it, how many weeks the test takes.
  2. 2Run keep/discard experiments with git and decide by verdict, with guardrails, a card, and human approval.
  3. 3Promote and roll back versions without deleting anything, and turn a lesson into a binding rule in AGENTS.md.
  4. 4Catch the agent that improves the score without improving the system, and measure the cost of each cycle.

Before you start

  1. 1Linux or macOS with git and Python 3. The rehearsals don't call any model.
  2. 2The public repositories loop-r and sil-loop-r cloned into ~/projetos (the kit reads both and never writes to them).
  3. 3Recommended: courses 0 to 4 of the track. This course points you to them when the topic belongs to them.
