Lesson 2 · 20 min

Experiment: keep or discard based on a single metric

The cleanest design for a loop that improves on its own is short: the agent changes one thing, a command gives the score, if it improved it stays with a commit, if it didn't it goes back with git reset, and everything becomes one line in a file. In this lesson you run this cycle with fake agents and then with the real Claude Code.

Start the lesson

In this lesson you will

  1. 1Keep = commit, discard = reset: git as undo
  2. 2A single metric, with a fixed budget per cycle
  3. 3results.tsv: every attempt becomes a line, including the bad ones
  4. 4The same cycle with a fake agent and with Claude Code

Goal: run an autoresearch-style experiment: the agent changes, a single metric decides, git commit if it improved and git reset if not.

Equal is not better: a tie goes to discard. Otherwise the system piles up changes that do nothing.

In autoresearch the system is a training script and the metric is validation loss; here, a triage classifier with 40 synthetic cases.

03 · Rehearsal: three fake agents

The kit creates a triage repo (v1) and runs three cycles: an agent that improves, one that makes things worse, and one that does not change the score. No model is called.

Terminal · cost-free rehearsal
K=~/projetos/loop-r-eng-aprende-v72/kit
E=${TMPDIR:-/tmp}/ensaio-aprende/a2
bash $K/novo-sistema.sh $E/sis
for m in sinonimos estraga comenta; do
  AGENTE="bash $K/agente-falso.sh $m" bash $K/experimento.sh $E/sis "$m"; echo "saída: $?"
done
echo "## results.tsv"; cut -f1,3- $E/sis/results.tsv
echo "## git log"; git -C $E/sis log --format=%s

Treating an agent with no answer as "did not improve". When your subscription hits its limit, the agent returns empty: the cycle must come out as an error (code 2), otherwise the queue turns into a series of false discards and nobody notices that nothing ran. agente-claude.sh exits with 1 when the answer has no rules, and experimento.sh records erro.

04 · The same cycle with Claude Code

One call through your subscription (uses your subscription quota): claude -p with no tools receives the rules and the wrong cases and returns a new regras.txt. The measurement decides, not the model.

Terminal · real, one call
K=~/projetos/loop-r-eng-aprende-v72/kit
E=${TMPDIR:-/tmp}/ensaio-aprende/a2      # the rehearsal repo above, already with the synonyms keep
AGENTE="bash $K/agente-claude.sh" bash $K/experimento.sh $E/sis "claude: uma mudança"; echo "saída: $?"
echo "status da última linha: $(tail -1 $E/sis/results.tsv | cut -f5)"
File · kit/agente-claude.sh
#!/usr/bin/env bash
# agente-claude.sh — o agente REAL do experimento: o Claude Code (sem ferramentas) propõe um regras.txt novo.
# Roda na pasta do repo, chamado pelo experimento.sh. Sai da cota da sua assinatura (uma chamada).
# Resposta vazia (limite da sessão, erro) = ERRO, saída 1: nunca vira "não mudou nada".
set -uo pipefail
K=$(cd "$(dirname "$0")" && pwd)
PEDIDO="Você melhora as regras de um classificador de mensagens de suporte. Formato de cada linha: 'categoria: palavra, palavra'; a primeira categoria cuja palavra aparece no texto vence; sem nenhuma, 'outros'.
Regras atuais:
$(cat regras.txt)

Casos que o classificador errou:
$(python3 "$K/medir.py" . --erros | tail -n +2)

Proponha UMA mudança que generalize (palavras que pessoas reais usariam), sem copiar frases inteiras dos casos.
Responda SÓ com o conteúdo completo do novo regras.txt, sem explicação e sem cercas de código."
J=$(mktemp)
echo "$PEDIDO" | claude -p --tools "" --output-format json > "$J" 2>/dev/null
python3 - "$J" <<'PY'
import json, os, sys
try:
    d = json.load(open(sys.argv[1], encoding="utf-8"))
except Exception:
    print("ERRO: resposta do claude não é JSON"); sys.exit(1)
r = (d.get("result") or "").strip()
linhas = [l for l in r.splitlines() if not l.startswith("```")]
if d.get("is_error") or not any(":" in l for l in linhas):
    print("ERRO: sem regras na resposta (" + (r[:80] or "vazia") + ")"); sys.exit(1)
u = d.get("usage") or {}
ent = u.get("input_tokens", 0) + u.get("cache_read_input_tokens", 0) + u.get("cache_creation_input_tokens", 0)
if os.environ.get("TOKENS_ARQ"):
    open(os.environ["TOKENS_ARQ"], "w").write(f"{ent} {u.get('output_tokens', 0)}\n")
open("regras.txt", "w", encoding="utf-8").write("\n".join(linhas).strip() + "\n")
print(f"regras.txt reescrito ({len(linhas)} linhas)")
PY
rc=$?; rm -f "$J"; exit $rc

One run. The model added delivery words (pacote, encomenda, transportadora, frete…) and the visible score went from 0.800 to 0.900. Your run may give keep or discard: the "done when" only checks that the line was recorded. In lesson 6, this same change is rejected by the hidden cases.

E6 · Your meter

30 min

In your system, write the command that prints the metric of your hypothesis (lesson 1) as a number on one line, in the format of medir.py --valor. Replace the medir.py in experimento.sh with yours (or adapt your system to the rules + cases format).

Done when: your measuring command, run twice in a row with no change, prints the same number; and a cycle with agente-falso.sh comenta adapted to your repo ends in discard.

07 · In three sentences

One change, one scoreEach cycle measures the baseline, lets the agent change one thing, and measures again with the same command.
Git undoesImproved is a commit; equal or worse is a reset. Nothing is left half done.
Everything loggedresults.tsv stores keep, discard and erro; an empty answer from the model is an error.
