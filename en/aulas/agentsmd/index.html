Lesson 5 · 18 min

Promotion to AGENTS.md and binding rule

An approved rule that lives only in a database does not reach a new session: it only exists if someone remembers to look it up. In this lesson you ask the promotion question, record the protection rung and the known leak, write the block into AGENTS.md with a diff first, and watch check flag it when someone edits the block by hand.

Start the lesson

In this lesson you will

  1. 1The promotion question, asked to the person
  2. 2The six rungs: prose, checklist, test, probe, hook, server
  3. 3promote shows the diff; --write writes the block
  4. 4check flags a missing, outdated, or edited block

Goal: mark the rule as binding with a rung and a leak, write the block into AGENTS.md with promote --write, and catch the edited block with check.

01 · From the active rule to the file every session reads

enforce, promote, and check (SIL Loop R 1.1.0). Click each block.

Moving up a rung is the remedy for a rule that slips: the busy-port lesson written three times calls for a hook, not a fourth line of text.

The gap that v1.1.0 closed: in v1.0.0, no rule reached AGENTS.md (sil-melhoramento/ANALISE.md, finding no. 1).

02 · The six protection rungs

Accepted values for --rung, from weakest to strongest. SIL records the rung; you build the hook or the test.

1. prose · checklist

The agent reads the rule (AGENTS.md, CLAUDE.md) or it is checked against a list. It leaks when the session doesn't read the file, or reads it and forgets.

Good for a rare rule or one that takes judgment.

2. test · probe

A test or a probe fails when the rule is broken. It leaks when nobody runs the test.

Wired into the loop gate (course 1, lesson 8), it no longer depends on memory.

3. hook · server

A hook blocks the tool before it runs, or the server refuses. It leaks through --no-verify, widened permissions, or another tool.

The guard hook is course 4, lesson 5.

Record the proofverify ID --positive … --negative … --evidence … stores the report of the cases you ran. It doesn't run or certify anything.

03 · Rehearsal: from enforce to the block in AGENTS.md

Continues the rehearsal from lesson 4 (R0001 active). At the end, what a session-start hook would inject.

Terminal · cost-free rehearsal
SIL=~/projetos/sil-loop-r/sil.py
E=${TMPDIR:-/tmp}/ensaio-aprende/a4; cd $E/p   # continues the lesson 4 rehearsal (R0001 active)
s() { python3 $SIL --project $E/p "$@"; }
j() { python3 -c 'import json,sys; d=json.load(sys.stdin); print(*[k+"="+json.dumps(d.get(k),ensure_ascii=False) for k in sys.argv[1:]])' "$@"; }
echo "# Instruções do projeto" > AGENTS.md
s enforce R0001 --binding yes --rung prose --leak "sessão que não lê o AGENTS.md" \
  --approved-by "Seu Nome" --reason "porta ocupada derruba o servidor de outra sessão" | j binding rung
s status | j promotion prose_binding; s check > /dev/null; echo "check: $?"
s promote | j written changed
s promote --write | j written; cat AGENTS.md
s check > /dev/null; echo "check: $?"
echo "## alguém editou o bloco à mão"; sed -i.bak 's/checar a porta/CHECAR A PORTA/' AGENTS.md
s check | j promotion; s check > /dev/null; echo "check: $?"
s promote --write | j written; s check > /dev/null; echo "check: $?"
echo "## o que um hook SessionStart injetaria"; s context --brief

Add the hooks block to the project's .claude/settings.json, without replacing the whole file; the last part of the rehearsal above shows the text that would go in. E14 · A binding rule of your own

20 min

Of the rules you adopted in lesson 4, ask the promotion question to whoever decides (you, if it's your project). For the one that is binding, record an honest rung and leak, look at the diff, and write it.

Done when: python3 $SIL --project . status | python3 -c 'import json,sys; print(json.load(sys.stdin)["promotion"]["in_sync"])' → True, and AGENTS.md has the block.

E15 · Climb a rung

30 min

Pick the binding rule that has already slipped (it shows up more than once in your lessons). Write a test or a probe that fails when it is broken, run one good case and one bad case, and record it with enforce --rung test (or probe) and verify.

Done when: your test exits with a code other than 0 on the bad case and 0 on the good case; and status no longer lists that rule in prose_binding.

07 · In three sentences

QuestionA binding rule is one whose breach, in a session without SIL, causes real damage; the person is the one who answers.
Blockpromote shows the diff, --write writes the delimited block, and check flags a missing or edited block.
